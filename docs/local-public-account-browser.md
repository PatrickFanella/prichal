# Public account browser link

Issue #155 uses its proposed link-out option. An owner with a completed first-account enrollment can open that account's public records and media in [PDSls](https://github.com/notjuliet/pdsls). The link appears in the existing first-account section after a valid, deployment-scoped enrollment read. Both `account_created` and `verified` states qualify; pending, missing, denied, unavailable or malformed data does not display a link. Local `.test` handles show an explanation because a public browser cannot resolve the local identity fixture.

The target has a fixed `https://pdsls.dev` origin and only the validated public `did:plc` identifier. The enrollment contract restricts it to the expected method and alphabet before rendering. DID colons remain literal because PDSls interprets a percent-encoded DID as a hostname. The link opens a separate tab with `noopener noreferrer` and `no-referrer`. It contains no management/native credentials, invitation, session, email or preference data.

Prichal makes no new public-record or PDSls requests, embeds no third-party content and acquires no native account authority. A slow or unavailable external browser cannot hold up the management page. The interface identifies PDSls as an independent service and explains that records/media are public and browsing needs no sign-in. This change does not implement record editing, a built-in paginator or member account enumeration. Existing owner-scoped enrollment authorization remains the source of the displayed DID; organization member hosting permissions remain separate work.

## October 15, 2026 verification

The T3 collaborative browser rendered the actual `FirstAccount` component and application styles in an ignored fixture page. Controlled API responses verified completed/unverified-email and verified accounts, local `.test` accounts, pending enrollment, foreign deployment IDs, malformed DIDs and 401/403/404/500 reads. Only valid public-account results exposed the link. The fixture observed zero mutations and no external resources loaded by the management page. Private machine-readable evidence is `.local/public-account-browser.json`; the page is `web/.local/public-records-check.html`.

At 320, 375, 667 and 1280 CSS pixels, the document matched viewport width and the new content had no horizontal overflow. Tab reached the link with a solid 3 px focus outline. Enter generated a trusted activation and opened a separate PDSls tab for the designated live pilot, which displayed `prichal-test.subcult.tv`, `app.bsky.feed.post` and the Blobs navigation. Its opener was null and its referrer empty. The source page remained available with zero mutations. A denied read on the existing three-second poll removed the link; successful reads restored it without remounting.

The full pinned smoke gate passed against separate PostgreSQL: 44 Node checks, production frontend build, Go vet and all race-enabled Go packages, including existing enrollment owner-isolation tests. The final URL correction also passed a fresh frontend production build. The package-manager bootstrap's incidental lockfile change was removed. No new dependency, backend route, schema, native mutation or production configuration changed.

This qualifies the source UI with controlled management responses and the external route against the existing live pilot. It does not enable production management enrollment, deploy the frontend, qualify a real signed-in owner's hosted journey or guarantee availability, pagination or authentication behavior of the independent browser. Those remain distinct from this bounded link-out feature.
