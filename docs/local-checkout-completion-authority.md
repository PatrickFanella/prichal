# Disposable checkout completion authority

The private numeric-loopback Node fixture can now model completion and current subscription state. It connects to no payment provider and processes no payments. Completion control is disabled unless separate private control and webhook key files are supplied after the runner's optional port argument. Arguments and the startup announcement contain no credentials.

The host-only control accepts an existing synthetic session, a UUID retry nonce, one supported completion type and explicit payment/subscription states. It rejects API credentials, browser Origin/Cookie headers (including empty headers), unknown sessions, expired open sessions, invalid transitions and extra ownership/catalog fields. Customer, subscription, configured Price and original request identity come from the retained registry. An atomic private write retains the current graph and notification together. Identical concurrent/restarted retries return the original event body with a fresh delivery signature; conflicting retries cannot change evidence. Control and signing keys are part of the registry scope, so enabling or changing them cannot silently reuse another authority's resources.

The fixed-version SDK reads the retained completed session and its current first-class subscription/item graph. Completion keeps the original session ID and expiry and removes navigation, even after the original expiry. Delayed-payment events can update explicit current evidence. The event registry and original request registry each have bounded capacity. The fixture sends no webhook or other outbound request: disposable tests deliver signed evidence explicitly.

The actual Node child, owner HTTP routes, real checkout/completion River workers, signed management HTTP intake and pinned SDK passed the focused race test. Two identical deliveries produce one notification/job, one original-owner verified binding/audit and one current unpaid/past-due observation. No pilot entitlement or native action is created, and the two original customer/session identities remain unchanged. Node tests also verify concurrent completion, restart, signatures, scope changes, forbidden credentials, invalid controls and expiry.

Full smoke with the populated snapshot opt-in passed, followed by a successful web build on current main with the merged Prichal branding. No schema or source runtime configuration changed.

Evidence is retained in ignored `.local/completion-authority-focused.log` and `.local/completion-authority-smoke.log`. Ordinary source billing remains disabled, with no source checkout requests or completion notifications. The retained native/container/credential custody hash remains unchanged. Since the earlier inventory, the running worker has aged out one completed deployment job older than a day; the monitor changed one deployment timestamp. Deployment fields apart from that timestamp and enrollment/access/admission counts match the retained recovery copy. These routine runtime changes mean the old whole-work hash no longer matches.

Interactive hosted browser completion, positive-state responsive coverage, commercial entitlement/grace policy, actual Stripe sandbox, independent backup custody and live qualification remain open. This authority is synthetic evidence and does not establish real-provider behavior or payment authorization.
