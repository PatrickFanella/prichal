## Operator contract

The helper remains `/usr/local/libexec/prichal/publish-managed-staging.py` on Almaz. It accepts complete generated endpoint inventories of 1–100 endpoints; handles remain closed until authoritative bindings are available. Existing forward listeners are an operator prerequisite. Manifests cannot supply an SSH target, credentials, upstream URL, file path or command. Each upstream stays `172.20.0.1:<reserved port>`, verified with its recorded public leaf, UUID TLS name and exact public service/OAuth identity.

For an update, pass `prepare --revision NEW_UUID --previous-revision CURRENT_UUID --bundle PRIVATE_BUNDLE --inventory-sha256 SHA256 --confirm-managed-inventory`. Then publish or roll back that retained revision with the same confirmation. `--confirm-staging-02` remains compatible but permits only the original fixture/port. Retained actions refuse preparation-only flags. Preparation creates private candidates/immutable trust, validates full Caddy and changes no active route.

The previous revision must have a matching root-owned inventory digest, successful marker and installed parent/route hashes. Rolled-back history cannot be adopted, and every new generation must exceed all published generations, including rolled-back ones. Omitted endpoints and changed hostname/forward mappings are refused. An explicit withdrawal or placement cutover requires its own procedure. Certificate digest changes are supported after fresh authoritative readback and actual TLS verification; this unit does not claim a native renewal drill.

Rollback validates the prior full JSON before changing route files and verifies that all preceding managed upstreams still work with their retained TLS trust. An expired export remains historical evidence of a prior publication; it is never new issuance authority. Expired/unusable TLS trust refuses rollback before mutation. A newer installed route also refuses an older rollback. All trust directories, inputs and receipts are retained.
