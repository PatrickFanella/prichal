# Disposable checkout authority fixture

Status: implemented and locally verified on October 1, 2026. Synthetic resources only; this creates no Stripe resource or charge.

A separate Node authority fixture supports only customer creation, hosted subscription checkout creation and exact expanded session reads. It requires a restricted test-shaped key, pinned API version, numeric-loopback binding, private state directory and fixed fixture Price/return origin. Browser Origin/Cookie requests, foreign customers, unsupported input, duplicate fields, replacement keys and oversized bodies are refused. There is no payment, Portal, webhook, subscription mutation or public binding route.

The private registry keeps separate original customer/checkout namespaces, canonical body digests, first-class resource IDs and the original expiry. Atomic file replacement commits a resource before acknowledging it. Repeated or concurrent exact calls return the original identity; changed bodies are refused. Fixture restart reloads the same scope and resources. Changed credential/catalog/return scope or public state permissions refuse startup. Capacity is bounded at one hundred original resources. Registry state includes no key plaintext, navigation URL, email or payment method.

The explicit runner accepts state/key-file paths and fixed configuration as arguments. It binds an ephemeral port on 127.0.0.1 and reports only the safe origin and `payments: false`. It reads credentials from a protected file and emits generic startup failures. This is isolated from the existing subscription-inbox fixture and ordinary source services.

Three Node tests passed for concurrent customer/checkout identity, original-key replay across fixture restart, unchanged registry on rejected retry, authentication/version/browser/body/custody refusal and expired reads without renewed expiry. A focused race integration started the actual Node process, a fresh disposable management database and the real River checkout worker. Real owner authorization/HTTP routes prepared a plan with no authority state, queued one original job despite retries, and the pinned SDK created the mapped customer and checkout. The job completed; repeated owner session reads preserved complete requests/audits/jobs. Two registry resources matched their original dispatch keys and saved SQL IDs. No binding, subscription observation, pilot grant or stored navigation appeared.

The test fixture directory explicitly uses 0700; an initial startup refusal confirmed that public directory permissions fail closed. The full local smoke gate passed, including the Node tests and actual River/SDK integration. Source work/native/custody and seven cancelled choices/fourteen audits match. Ordinary schema-32 API, worker and billing-session configuration remain unchanged. Optional golangci-lint remains unavailable.
